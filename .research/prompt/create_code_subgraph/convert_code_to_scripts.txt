We replace the fixed σ(βΔ) with p̂ = σ(α·Δ/σ_b) where σ_b is a running RMS of Δ in the current mini-batch and α is a single learnable scalar initialised to 1.  Because the Brier family is strictly proper, α is identifiable and converges to the inverse optimal temperature, removing all manual β sweeps. 2) Count-aware soft labels.  A pair that has been judged k_w times as winner and k_l times as loser is assigned a Beta(k_w+1,k_l+1) posterior.  The target probability is y = (k_w+1)/(k_w+k_l+2) and its epistemic uncertainty u = 1/(k_w+k_l+2). # Experimental Design
- Strategy: ────────────────────────────────────────────────
Experiment 1 – Head-to-Head Alignment Benchmark
Purpose: Show that SC-PSPO is a true drop-in replacement that beats tuned baselines while using zero manual β tuning.
Design
1. Models:  Llama-2-7B-chat (primary) and Zephyr-7B-Gemma-SFT (replication).
2. Data:  Argilla-DPO-Mix-7 K (binary) + Reddit TL;DR (soft counts) concatenated.
3. Methods:  SC-PSPO, DPO, DiscoPOP, GDPO, BPPO.  Each gets exactly one run with the hyper-parameters given in the proposal; baselines use the authors’ recommended β or default grid-search file where required.
4. Hardware: one A100-80 GB per run, gradient accum. so that effective batch = 64.
5. Metrics
   • Quality: MT-Bench and AlpacaEval win-rate versus GPT-4.
   • Calibration: ECE and −log likelihood on a 10 k held-out preference set.
   • Stability: max grad-norm, % runs diverged (5 seeds).
   • Throughput: tokens / s.
Pass / Fail Criteria
SC-PSPO must (i) match or exceed the best tuned baseline’s win-rate, (ii) cut ECE by ≥50 %, and (iii) show zero divergence without gradient clipping.
Demonstrates: practical superiority in quality, calibration, and stability while eliminating β sweeps.
────────────────────────────────────────────────
Experiment 2 – Robustness to Noisy or Adversarial Votes
Purpose: Validate the uncertainty-weighting mechanism and bounded gradient under extreme label noise.
Design
1. Take 1 k preference pairs from the Human Harmless subset.  For each pair, synthesise extra “votes” so that the empirical y∈{0,0.25,0.5,0.75,1}.  Also generate 20 % adversarial flips (winner↔loser).
2. Train three fresh Llama-2-7B copies on only these 1 k pairs for 500 steps via (a) SC-PSPO, (b) DPO with β tuned, (c) BPPO.
3. Log per-step loss, grad-norm, and accuracy on a clean validation slice (no corruption).
4. Extend corruption level from 0→60 % in a controlled sweep; repeat once per level.
Metrics
   • Convergence rate: steps to reach 80 % clean-set accuracy.
   • Failure rate: runs that diverge or whose grad-norm >10.
   • Final ECE on clean validation.
Demonstrates: SC-PSPO’s epistemic down-weighting and bounded gradient keep training stable and calibrated even when labels are extremely unreliable, whereas baselines become brittle or explode.
────────────────────────────────────────────────
Experiment 3 – Vote-Count Efficiency Study
Purpose: Show that SC-PSPO extracts extra performance from multiple votes per pair, enabling cheaper data collection strategies.
Design
1. Reddit TL;DR has 5 GPT-4 votes per pair.  Construct four training settings:
   S1 – Majority vote (1 bit)  •  S2 – 3 random votes  •  S3 – all 5 votes  •  S4 – 5 votes + an extra synthetic vote so total = 6 (tests diminishing returns).
2. For each setting, subsample the dataset so that the total number of human-labels processed is identical (e.g., fewer pairs when more votes per pair).
3. Train SC-PSPO and DPO (majority only) for two epochs; evaluate on MT-Bench + calibration set.
4. Compute “label-cost-adjusted quality” = win-rate ÷ total votes consumed.
Expected Outcome
   • SC-PSPO’s win-rate rises monotonically S1→S3 and plateaus at S4, giving 15–25 % higher cost-adjusted quality than DPO.
   • DPO shows no benefit from extra votes because it collapses them to a single bit.
Demonstrates: the count-aware soft-label design yields tangible sample-efficiency gains and makes crowdsourcing with repeated votes economically attractive.
────────────────────────────────────────────────
If all three experiments succeed, we have evidence from complementary angles—raw benchmark strength, robustness under noise, and sample efficiency—that SC-PSPO is a superior, temperature-free replacement for current preference-learning losses.
- Details: ────────────────────────────────────────
GLOBAL SETTINGS (apply to all three experiments unless over-ridden)
1. Framework & Tooling
   • PyTorch 2.2 + Flash-Attention-2, Transformers v4.40.  
   • A100-80 GB (sm8x) in BF16 mixed-precision; ZeRO-2 off-loading disabled (fits in memory).  
   • Every run is wrapped with torch.cuda.profiler to collect wall-clock time, peak-memory, and kernel-level FLOPs (nvtx marks added).  
   • Seeds = {11,13,17,19,23}.  cuRAND and Python’s random are seeded; deterministic kernels are not forced to avoid speed loss.
2. Optimiser, Scheduler, Regularisers
   • AdamW(β1 = 0.9, β2 = 0.95, ε = 1e-8)  
   • LR = 5e-7, linear warm-up 5 % of steps, cosine decay to 90 %.  
   • Weight-decay 0.1 on non-norm, non-bias parameters.  
   • No gradient clipping for SC-PSPO; 1.0 clip-norm for other losses per authors’ default.  
   • Dropout 0.05 (attention + MLP) across all models for fairness.
3. DataLoader & Tokenisation
   • SentencePiece 32 k Llama tokenizer.  
   • Max sequence len 2 048 tokens, packed in conversation pattern: 〈|user|〉prompt〈|assistant|〉answer.  
   • Bucketing by length, dynamic padding on GPU, num_workers = 8, pin_memory = True.
4. Logging & Reproducibility
   • Weights & Biases project = "SC-PSPO"; every run uploads config, git-hash, docker hash.  
   • A YAML spec of each run is committed to a versioned configs/ folder to satisfy drop-in claim.

EXPERIMENT 1 – Head-to-Head Alignment Benchmark
Purpose: show SC-PSPO beats tuned baselines without β-sweeps.
A) Models
   Primary : Llama-2-7B-chat-HF
   Replica : Zephyr-7B-β-Gemma-SFT (HuggingFace ID = "HuggingFaceH4/zephyr-7b-beta")
   Baselines: same checkpoints, different preference-loss wrappers.
B) Datasets
   1. Argilla-DPO-Mix-7K (binary)
   2. Reddit TL;DR preference pairs with 5 GPT-4 votes each (soft counts)
   3. Held-out calibration set = 10 k pairs sampled 40 / 60 from (1)/(2)
   Combined training size ≈ 45 k pairs.
Pre-processing
   • Remove pairs where either answer ≥2 048 tok.  
   • De-duplicate by (prompt,answer_a,answer_b) after lower-casing.  
   • Map (k_w,k_l) as described; Argilla pairs get k_w = 1,k_l = 0.
Splits
   • 80 % train, 10 % validation, 10 % test (stratified by dataset id).  
   • Validation is used only for early-stopping baselines; SC-PSPO trains full 2 epochs.
C) Runs & Hyper-params
   • Methods = {SC-PSPO, DPO, DiscoPOP, GDPO, BPPO}.  
   • Each method × model × seed → 10 distinct GPU runs.  
   • Effective batch = 64 by grad-accum × 4 (physical batch 16) so that A100 memory stays <70 GB.
Selection / Averaging
   • Report test metrics averaged across 5 seeds.  
   • Quality metrics are reported as "best-val" because AlpacaEval/MT-Bench inference is expensive; others (ECE, throughput) use last checkpoint.
D) Metrics
   Primary   : MT-Bench win-rate vs GPT-4-Turbo; AlpacaEval win-rate.
   Secondary : ECE (15-bin), NLL on held-out prefs; throughput (tok/s); max grad-norm; divergence count.
E) Analytical Add-ons
   • Hyper-param sweeps (lr ∈ {2e-7,5e-7,1e-6}, α_lr ∈ {2e-4,5e-4,1e-3}) on a single seed for SC-PSPO to visualise robustness heat-map.
   • FLOPs/training-time computed via PyTorch Profiler: aggregate encoder/decoder TFLOP and divide by wall-clock for "TFLOP/s".  
F) Expected Compute Budget
   • 45 k pairs × 2 k tok × 2 epochs ≈ 180 M tokens.  
   • 7B param → ≈350 GFLOP / fwd+bwd step.  
   • 180 M /64 ≈ 2.8 M steps → 980 TFLOP/run ≈ 0.27 GPU-hr (A100 ~3.6 TFLOP/s BF16) → 2.7 hr/run.
G) Example Launch Snippet

EXPERIMENT 2 – Robustness to Noisy / Adversarial Votes
A) Dataset Construction
   • Start from Human-Harmless-500 (public subset of Anthropic HH).  
   • For each pair with majority label, replicate votes until y ∈ {0,0.25,0.5,0.75,1}.  
   • Add controlled adversarial flips: noise level p ∈ {0,0.2,0.4,0.6}.  
   • Dataset size fixed at 1 000 pairs for train, 200 clean pairs for validation.
B) Models
   • Three freshly initialised copies of Llama-2-7B-chat (same starting weights).  
   • Losses: SC-PSPO, DPO(β best-of-grid {0.1,0.5,1,2}), BPPO(β = 1).
C) Training Regime
   • 500 optimisation steps, batch = 32 (no grad-accum).  
   • Fixed LR = 1e-6 to highlight instability.
D) Sweep Protocol
   • For each p, run all three methods once (same seed = 42) ⇒ 12 runs.  
   • Log step-wise loss, grad-norm (torch.nn.utils.clip_grad_norm_ w/out clipping), clean-val accuracy.
E) Metrics & Plots
   • "Steps-to-80 %" measured via first epoch where accuracy≥0.8.  
   • Divergence flag when grad-norm>10 or loss=NaN.  
   • ECE on clean-val after final step.  
   • Robustness curve plotted: p vs (accuracy, ECE, divergence-rate).
F) Robustness Analysis
   • Statistical test: Cochran’s Q across methods for divergence counts.  
   • Sensitivity of α (learned temperature) plotted over steps.
G) Expected Compute
   • 500 steps × 2 k tok × 3 methods × 4 noise levels ≈ 12 M tokens → < 30 min total.

EXPERIMENT 3 – Vote-Count Efficiency Study
A) Dataset Partitioning (Reddit TL;DR)
   • Original: 12 k pairs × 5 votes.
   • Settings
        S1 Majority : keep all pairs, collapse labels.
        S2 Three  : sample 3 votes, derive Beta posterior.
        S3 Five   : use all 5 votes (default).
        S4 Six   : sample 5 + synthetic extra vote = k_w+1,k_l (if y>0.5) else reverse.

        − S1 uses P1 = 12 k pairs (12 k votes).  
        − S2 uses P2 = V_total/3 ≈ 4 k pairs.  
        − S3 uses P3 = V_total/5 ≈ 2.4 k pairs.  
        − S4 uses P4 = V_total/6 ≈ 2 k pairs.
B) Methods
   • SC-PSPO (all settings).  
   • DPO (only S1, majority-vote) as label-cost baseline.
C) Training
   • Llama-2-7B-chat, 2 epochs, batch = 64, all other global hyper-params.
D) Evaluation
   • MT-Bench + AlpacaEval as in Exp-1.  
   • Cost-adjusted quality = win-rate / V_total.  
   • 3 seeds {11,17,23}; report mean ± SEM.
E) Additional Analysis
   • Compute marginal utility Δ(win-rate) per extra vote.
